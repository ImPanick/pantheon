# Core dependencies, pinned to exact versions.
#
# WHY EXACT PINS (`B320`). Every line in this file used to be a bare name or an
# open floor, and that had three consequences:
#
#   1. The build was not reproducible. `docker build` on two different days
#      produced two different images from the same commit, and "it worked
#      yesterday" had no answer.
#   2. A yanked, broken or compromised release landed on the next build with
#      nothing in between. There was no version anybody had agreed to.
#   3. `.github/dependabot.yml` was decorative for the pip ecosystem. Dependabot
#      opens a pull request when a *pinned* version falls behind; a bare
#      `fastapi` is satisfied by every release ever made, so there was never
#      anything to bump and the config looked like coverage while providing
#      none.
#
# Pinning fixes all three at once. The point is not that today's versions are
# special -- it is that the version is now a decision somebody makes in a
# reviewable diff instead of a side effect of build timing.
#
# HOW THESE STAY CURRENT. Dependabot (pip ecosystem, weekly, grouped) now has
# something to compare against and opens a bump PR when any pin falls behind.
# `.github/workflows/dependency-review.yml` audits the pinned set against the
# advisory database on every push and pull request and **fails** on a known
# vulnerability -- see `.pantheon/dependency-advisories.toml` for the register
# of accepted risks and the reasoning behind each one.
# `.pantheon/check-pins.py` runs offline in the release gate and fails if a new
# dependency is added without a pin.
#
# HOW TO RE-PIN BY HAND. The authority is the image, not PyPI:
#
#     docker build -t pantheon:pin .
#     docker run --rm pantheon:pin pip freeze
#
# and copy the versions of the packages named below. Versions in this file were
# resolved on 2026-09-16 for CPython 3.11 (CI) through 3.14 (the image) under
# the constraints recorded beside each entry; see `B320` for what was measured.
#
# Constraint ranges that used to be on the requirement line are kept as comments
# beside the pin. They are the reason the pin may not move past a boundary, and
# deleting them would lose that reason.
