# Pantheon 0.1.0 — release notes

The first release line of Pantheon, written for two readers: someone meeting it for the first
time, and someone running Odysseus who wants to move. Every figure below was measured on the tree
these notes were written against (`595d1bd`, 2026-10-02) or on Odysseus at the fork point, and the
[sources](#sources) say where. The rename tables are checked against the lists that own them by
`tests/test_the_release_notes_name_every_rename.py`, so a name the tree gains or loses fails a test
rather than going stale here.

## Pantheon is a fork of Odysseus

**Pantheon is a modified version of [Odysseus](https://github.com/pewdiepie-archdaemon/odysseus),
created by `pewdiepie-archdaemon`.** Odysseus's own code and documentation also point at a second
name for the same project, [`odysseus-dev/odysseus`](https://github.com/odysseus-dev/odysseus);
`NOTICE` credits both.

- **What it is.** A self-hosted AI workspace. Its first commit is `e5c99a5`, *"Odysseus v1.0"*, by
  `pewdiepie-archdaemon` on 2026-05-31. By the fork point it had **2,073 commits** under
  **344 distinct author names** — `pewdiepie-archdaemon` wrote 559 of them.
- **What came from it.** The agent loop, the tool layer, the approval and untrusted-content security
  model, the window system, the theme engine, the skills system, the task scheduler, the MCP
  integration, the email client, the image editor and the research pipeline all began there
  (`CREDITS.md`). The hard parts were already solved; Pantheon's work is surfacing, wiring and
  building on them.
- **Licence.** Odysseus is released under **AGPL-3.0-or-later**, and so is Pantheon. The original
  authors keep copyright over the parts that originate with them (`NOTICE`).
- **The fork point** is commit `b4d1293` (`b4d12932a953b3cdfc745b3525c7ecd5dffd8b3c`) on upstream's
  `dev` branch, *"fix(agent): drop the empty assistant turn from an approved-action replay
  (#6124)"* — authored `2026-08-20T05:06:22-06:00`, committed `2026-08-20T13:06:22+02:00`.
  **2026-08-20** is that commit's date.
- **The fork's start** is **2026-08-24, in UTC**: the first commit on top of `b4d1293` is
  `a4c4456` (*"feat(local): lift guardrail caps for self-hosted inference; keep them for cloud
  APIs"*), dated `2026-08-23T16:37:07-08:00`, which is `2026-08-24T00:37:07Z`. That is the *Date of
  fork* `NOTICE` gives.
- **What has come back from upstream since:** five fixes, cherry-picked with their authors kept
  (`P19-06`) — `rauljua`, `Vykos`, `daixiheguu`, `cybernetus@xda` and `RaresKeY`. Nothing else
  after `b4d1293` is in Pantheon, and nothing in these notes was measured against a later Odysseus.

Pantheon is not affiliated with or endorsed by the Odysseus project under either name. Please do
not send them Pantheon's issues. For Odysseus itself, contribute
[upstream](https://github.com/pewdiepie-archdaemon/odysseus).

## What Pantheon is

A self-hosted AI workspace — chat, agents, research, documents, email, notes, calendar and local
model serving, on hardware you own. The programme is *elevation, not rewrite* (`.pantheon/AGENTS.md`):
features Odysseus had survive (`Law 1`), and the work went into the surface, the wiring and the
rooms the engines lacked. Two rules shape every default: nothing leaves the machine until a person
links it (`Law 16`), and a feature that needs a tutorial is not finished (`Law 15`).

## Which version this is

- **`0.1.0`.** One constant carries it — `APP_VERSION` in `src/constants.py` — and
  `GET /api/version`, `GET /api/readiness` and the `pantheon_build_info` metric all read it
  (`CHANGELOG.md` § Versions). `pantheon --version`, and `--version` on the commands built on
  `scripts/_lib/cli.py`, print the same string.
- **It is not tagged yet.** The tag `v0.1.0` is cut on the commit that is released, by the person
  cutting it — `CHANGELOG.md` § Versions says how. `CHANGELOG.md`'s `[0.1.0]` heading is dated
  2026-09-17, the day the version line was set (`B450`); every build since reports `0.1.0`,
  because the version names a line, not a commit (`B453`). These notes describe the tree as it
  stands on 2026-10-02.
- **`0.x` is a statement about support.** `SECURITY.md` supports `main` and nothing else.
  `1.0.0` is the first release that is public, tagged *and* supported. The repository has been
  public since 2026-10-02 (`D-2026-10-02-03`).

## Breaking renames — coming from Odysseus

Everything called *Odysseus* became *Pantheon* in one mechanical sweep (`scripts/pantheon-init.sh`,
`P0-01b`): `odysseus` → `pantheon` in each of its three cases, and the short `ody` before a `-`,
`.` or `_` → `pan`. **There is no compatibility shim.** Pantheon reads none of the old names, with
one exception — API tokens minted as `ody_…` are still honoured (`core/api_tokens.py`,
`ACCEPTED_TOKEN_PREFIXES`) — so every name below that you set, script against or store is yours to
change.

**What did not change:** the port (`7000`), the ChromaDB, SearXNG and ntfy services, the three
named volumes, the settings keys (no `DEFAULT_SETTINGS` key or default value carries the name), the
database files in the data directory, the built-in MCP server ids, the Cookbook's routes and keys
(the label a person reads is *Forge*, `D-2026-09-18-04`), and the backup format (`"version": 1`
in `routes/backup_routes.py` at the fork point and now).

  choose:** `workstation` and `workstation-net` (`docker/workstation.yml`,
  `docker/workstation-vm.yml`).
- **The named volumes keep their names:** `chromadb-data`, `searxng-data`, `ntfy-cache`. New with

  `workstation-vm`.
- **But Compose prefixes every volume with the project name, which is the checkout's directory.**
  Measured with `docker compose config` (Compose v5.1.3) on this tree's `docker-compose.yml`: in a
  directory named `odysseus` the volumes are `odysseus_chromadb-data` and so on; in a fresh clone

  clone's own, empty, directory. Setting `COMPOSE_PROJECT_NAME=odysseus` and
  `APP_DATA_DIR=<old checkout>/data` in `.env` points the new clone back at both.
- **The image.** Odysseus's compose file named no image for its build; Pantheon's names it
  `ghcr.io/impanick/pantheon:latest`. Whether a published image exists has not been checked

- **The macOS bundle id is a new identity to the OS** (`.pantheon/FORBIDDEN.md`, *Renames that ARE

## What is new, phase by phase

The tracker is `.pantheon/ROADMAP.md`; each phase below names its rows. A few honest lines each —
what a person can do now that they could not in Odysseus.

- **The Workbench (`P22`, closed 2026-10-02).** One window, three rooms. *Automations*: a workflow
  is one named document on a canvas, started by one scheduled task (`D-2026-10-01-05`); steps are
  wired *if it works* / *if it fails*; a step picks a field from what earlier steps made, and a
  setting that decides what runs, where it goes or who it reaches never takes one (`P22-09`); If,
  Switch and Set without code (`P22-10`); branches that meet at a Merge, and a Wait that survives a
  restart (`P22-11`); For each (`P22-12`); HTTP through an Integration, MCP tools, skills, an AI
  step held to the tools it names, and code that runs in your own workstation (`P22-13` …
  `P22-16`, `P22-18`). *Show me what this would do* plans a whole chain and runs nothing
  (`P22-04`). A step a model drives waits up to twelve hours for a person's yes (`P22-17`,
  `D-2026-10-02-01`). Say what should happen and the model drafts it switched off, every step marked

  module; *MCP & Integrations* builds an MCP server in your workstation and tries it before an admin

## Upgrading from Odysseus

Measured against Odysseus at `b4d1293`. If you run a later Odysseus it has changes Pantheon does
not, and nothing here was checked against them.

**Before — on the Odysseus install**

1. **Back up** `.env` and the data directory (`./data`; `~/.odysseus/data` for a frozen desktop
   build).
2. **In every browser you use it from**, export your custom themes and send or copy any unsent mail
   reply or unsaved note — they live in browser storage under names Pantheon does not read.
3. **Stop it.** Docker: `docker compose down` in the Odysseus checkout — Pantheon's compose service
   is `pantheon`, so its compose file does not stop a container named for `odysseus`. Native:
   `sudo systemctl disable --now odysseus-ui` if you installed the unit.

**Switch**

4. **Keep your data where Compose will look.** Either switch the existing checkout to Pantheon —
   same directory, same project name, same volumes and `./data` — or, in a fresh clone, set
   `COMPOSE_PROJECT_NAME` to the old directory's name and `APP_DATA_DIR` / `APP_LOGS_DIR` to the old
   `data` and `logs` in `.env`.
5. **Rename every `ODYSSEUS_` variable** to `PANTHEON_` — in `.env`, in a systemd
   `EnvironmentFile`, in shell profiles and in CI. In `.env` alone:
